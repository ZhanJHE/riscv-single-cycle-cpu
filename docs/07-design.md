# 07 · 设计文档

本文说明这份单周期 CPU 的设计目标、执行过程、各模块的设计要点与关键设计决策。
模块端口明细见 [04 · 模块参考](04-module-reference.md)，模块连接关系见
[02 · 架构与数据通路](02-architecture.md)，指令编码与控制真值表见
[03 · 指令集参考](03-instruction-set.md)。

> 本文档描述的是仓库中的实际代码。早期版本（原 `sCPULab.srcs/README.md`）
> 中的示意代码与实际实现不一致，已按实际代码重写并移入本目录。

## 1. 设计目标

用 Verilog 实现一个可以在 FPGA 上运行的 RISC-V 32 位单周期 CPU，作为
计算机组成原理课程的教学实验。

| 项 | 决定 |
|---|---|
| 指令集 | RV32I 子集，23 条指令（见下） |
| 执行方式 | 单周期：每条指令在一个时钟周期内完成全部操作 |
| 指令存储器 ROM | 64 字 × 32 位，起始地址 `0x00400000` |
| 数据存储器 RAM | 256 字 × 32 位，按字访问 |
| 通用寄存器 | 32 个 × 32 位（x0 恒为 0） |
| 验证方式 | 自检程序 + 黄金值逐周期比对（见 [05](05-verification.md)） |

23 条目标指令：

- 运算类：`add` `sub` `xor` `or` `and` `sll` `srl` `sra`、`addi` `andi` `ori` `xori` `slli` `srli` `srai`
- 访存类：`lw` `sw`
- 分支类：`beq` `blt` `bltu`
- 跳转类：`jal` `jalr`
- 立即数类：`lui`

其中 `jalr` 已实现但自检程序未覆盖；自检程序覆盖其余 22 种。

## 2. 术语表

| 术语 | 含义 |
|---|---|
| 单周期 CPU | 每条指令在一个时钟周期内完成取指到写回的全部操作 |
| 时钟周期 | 时钟信号相邻两次上升沿之间的时间，本项目仿真中为 10ns 或 20ns |
| 时钟上升沿 | 时钟信号由低变高的瞬间。寄存器类电路（PC、寄存器堆、RAM 写口）只在这一时刻更新 |
| 取指 | 按照当前 PC 的值，从指令存储器中读出指令 |
| 译码 | 从指令的 32 位编码中解析出各字段（操作码、寄存器号、立即数等） |
| 执行 | 由运算单元（ALU）完成算术、逻辑、移位或地址计算 |
| 访存 | 对数据存储器 RAM 进行读取（lw）或写入（sw） |
| 写回 | 把执行结果写入寄存器堆 |
| 数据通路 | 指令执行所经过的全部部件和连线 |
| PC | 程序计数器（Program Counter），保存当前正在取指的指令地址 |
| 操作码 (opcode) | 指令的第 `[6:0]` 位，决定指令属于哪一类 |
| 功能码 (funct3/funct7) | 同一操作码内进一步区分具体运算的位段 |
| 立即数 | 直接写在指令编码里的常数，不需要读寄存器 |
| 符号扩展 | 把较短位宽的有符号数的高位全部填成其符号位，扩展到更长位宽，数值不变 |
| 写使能 (we) | 使能信号，为 1 时才允许写入；为 0 时写入被忽略 |
| 同步复位 | 复位信号在时钟上升沿才生效，而不是立刻生效 |
| 高有效 | 信号为 1 表示有效 |
| 字 (word) | 32 位数据单位。本项目存储器按字编址：字节地址除以 4 得到字索引 |
| 组合逻辑 | 输出只由当前输入决定、不记忆历史的电路 |
| 时序逻辑 | 在时钟沿更新状态、其余时间保持的电路 |
| 黄金值 | 预先算好的期望结果（PC 和寄存器值序列），用于和仿真实际值自动比对 |
| RV32I | RISC-V 32 位基础整数指令集 |

## 3. 总体结构

`top.v` 是仿真顶层，内含三个模块：

```
top.v
├── mycpu   (CPU.v)   数据通路，内部例化五个子模块
│   ├── mypc    (pc.v)            程序计数器
│   ├── myid    (ID.v)            指令译码器
│   ├── mycu    (ControlUnit2.v)  控制单元
│   ├── myrf    (RegFiles.v)      寄存器堆
│   └── myalu   (alu.v)           运算单元
├── insrom  (rom.v)   指令存储器
└── dataram (ram.v)   数据存储器
```

连接关系概括为一句话：PC 给出地址，ROM 送出指令，ID 解析字段，控制单元发控制
信号，寄存器堆和立即数向 ALU 提供操作数，ALU 的结果写回寄存器堆或用于访问
RAM，下地址逻辑决定下一条指令的位置。完整的信号连接图见
[02 · 架构与数据通路](02-architecture.md)。

## 4. 一条指令的执行过程

以自检程序的第一条指令 `ori x1, x0, 0x789`（把 0x789 写入 x1）为例。
以下 8 步在同一个时钟周期内按组合逻辑顺序完成，最后一步是唯一的状态更新时刻。

| 步骤 | 动作 | 本例中的数据 |
|---|---|---|
| 1 取指 | PC 的值 `0x00400000` 经 `[9:2]` 折算成字索引 0，ROM 输出指令字 `78906093` | 指令 = `78906093` |
| 2 译码 | ID 解析出各字段 | opcode=`0010011`，rs1=x0，rd=x1，imm12=0x789 |
| 3 控制 | 控制单元按 opcode/funct3 输出控制信号 | regWe=1，bIsImm=1，aluOp=`0110`（或运算） |
| 4 读寄存器 | 寄存器堆按 rs1/rs2 输出两个操作数 | rdata1 = x0 的值 = 0 |
| 5 选择操作数 | b 选择器按 bIsImm 选中立即数 | b = 0x789（符号扩展自 imm12） |
| 6 执行 | ALU 完成或运算 | f = 0 或 0x789 = 0x789 |
| 7 选择写回与下地址 | 写回选择器选 ALU 结果；下地址选择器按 pcSourceCode=00 选 PC+4 | rwdata = 0x789，nextaddr = `0x00400004` |
| 8 时钟上升沿 | 寄存器堆写入 x1=0x789；PC 更新为 `0x00400004` | 状态更新 |

分支和跳转指令的不同之处只在第 7 步：分支指令由 ALU 输出条件 `con`，
`con=1` 时下地址选择器改选分支目标地址；`jal`/`jalr` 无条件改选跳转目标，
并把 PC+4 写回 rd（作为返回地址）。

## 5. 各模块设计

每个模块只列职责与关键设计点。端口定义、时序与已知问题见
[04 · 模块参考](04-module-reference.md)。

### 5.1 top.v — 顶层

- 例化 CPU、ROM、RAM 三个模块并连线。
- ROM 地址取 PC 的 `[9:2]`：丢弃低 2 位，把字节地址换算成字索引。
- RAM 通过 CPU 的 `mem*` 端口连接（见 5.2）。

### 5.2 CPU.v — 数据通路

把五个子模块连成完整通路，另含三处多路选择器和一个存储器接口。
三处多路选择器是数据通路的决策点，由控制单元的信号驱动：

| 选择器 | 问题 | 控制信号 | 候选 |
|---|---|---|---|
| b 操作数 | ALU 的第二个操作数是谁 | `bIs20bImm` / `bIsImm` | 20 位立即数（lui）/ 12 位立即数符号扩展（I 型、访存）/ 寄存器 rdata2（R 型、分支） |
| 写回数据 | 什么值写入寄存器堆 | `regDataIsFromMem` / `regDataIsFromPC4` | RAM 读数（lw）/ PC+4（jal、jalr）/ ALU 结果 |
| 下地址 | 下一条指令在哪 | `pcSourceCode` + `con` | PC+4 / 分支目标（con=1 才选）/ jal 目标 / jalr 目标 |

关键计算公式：

- 分支目标 = `PC + 符号扩展({imm12, 1'b0})`。ID 输出的 imm12 对 B 型指令是
  imm[12:1]，最低位按编码约定恒为 0，所以拼接时补一个 0。
- jal 目标 = `PC + 符号扩展({imm20, 1'b0})`，原理同上。
- jalr 目标 = `(rs1 + imm12) & ~1`，最低位清 0 是 RISC-V 规范要求。
- RAM 地址 = `f[9:2]`，与 ROM 相同的字索引换算方式；写数据固定为 rdata2。

### 5.3 pc.v — 程序计数器

- 每个时钟上升沿更新为 nextaddr；无写使能、无暂停功能（单周期每拍必取新指令）。
- 同步复位、高有效，复位值 `0x00400000`，即 ROM 的首地址。

### 5.4 rom.v — 指令存储器

- 64 字 × 32 位，组合逻辑读（地址变化立即出数）。
- 用 `$readmemh` 从文本文件 `insData.txt` 读入 26 条自检指令。该写法只在
  XSim 仿真下有效，综合时需改用 Block Memory IP 加 COE 文件（见
  [06 · 步骤 6](06-status-and-roadmap.md)）。

### 5.5 ID.v — 指令译码器

- 字段提取是纯连线：opcode=`ins[6:0]`、rd=`ins[11:7]`、funct3=`ins[14:12]`、
  rs1=`ins[19:15]`、rs2=`ins[24:20]`、funct7 输出 `ins[30]`（用于区分
  add/sub、srl/sra）。
- 立即数按指令类型拼装，类型之间用与门掩码隔离：

| 类型 | 12/20 位立即数来源 |
|---|---|
| I（addi 等、lw、jalr） | `ins[31:20]` |
| S（sw） | `{ins[31:25], ins[11:7]}` |
| B（分支） | `{ins[31], ins[7], ins[30:25], ins[11:8]}`，即 imm[12:1] |
| U（lui） | `ins[31:12]` |
| J（jal） | `{ins[31], ins[19:12], ins[20], ins[30:21]}`，即 imm[20:1] |

- U 型与 J 型共用 20 位输出端口 `imm20`；CPU 端按类型决定怎么用
  （lui 直接做 ALU 输入，jal 左移 1 位后加到 PC）。

### 5.6 ControlUnit2.v — 控制单元

- 组合逻辑：`always @(*)` + `case(opcode)`。所有信号先赋默认值（等价于 nop），
  再按指令类型改写，避免遗漏分支产生锁存器。
- R 型与 I 型运算按 funct3 译码，funct7（`ins[30]`）区分 add/sub 与 srl/sra。
- 分支类指令一律输出 `pcSourceCode=01`，是否真的跳转由 CPU 端的 `con` 决定。
- `condition` 输入端口保留（兼容原接口），控制单元内部不使用它。
- 完整真值表见 [03 · 控制真值表](03-instruction-set.md)。

### 5.7 alu.v — 运算单元

- 4 位操作码，16 种运算：算术（加、减）、逻辑（与、或、异或）、移位
  （左移、逻辑右移、算术右移）、比较（相等、不等、有符号/无符号小于、
  有符号/无符号大于等于）、地址计算（jalr）、lui。完整表见
  [02 · ALU 操作码表](02-architecture.md)。
- 移位量只取第二个操作数的低 5 位（`dataB[4:0]`），这是 RV32I 的规定
  （32 位数的移位范围是 0–31）。
- 比较类运算把判断结果放到 `con` 输出，供分支使用；`slt`/`sltu` 同时把
  结果放到 `result`。
- lui 操作由 ALU 把 20 位立即数左移 12 位完成，低 12 位补 0。

### 5.8 RegFiles.v — 寄存器堆

- 31 个寄存器（`regs[1:31]`）加一个硬连线的 x0。
- x0 恒为 0：读取时直接返回 0；写入地址为 x0 时忽略写操作。这是 RISC-V
  的规定，x0 用作"零常数"。
- 异步读（地址变化立即出数）、同步写（时钟上升沿且写使能有效时写入）。
- 仿真用 `initial` 语句把所有寄存器清零；该写法在 Vivado 综合时转换为
  FPGA 上电初值。

### 5.9 ram.v — 数据存储器

- 256 字 × 32 位，同步写、异步读。
- 上电内容不确定（仿真中为 x）；自检程序先用 `sw` 写入再用 `lw` 读出，
  不依赖初始值。

## 6. 关键设计决策

| 决策 | 理由 |
|---|---|
| 采用单周期而不是多周期/流水线 | 结构最简单，一条指令的行为可以用一条路径解释清楚，便于教学和调试。代价是时钟频率受限于最慢的组合逻辑路径（取指→译码→ALU→写回） |
| PC 复位值为 `0x00400000` | 与 ROM 的基地址一致。ROM 地址取 `pcAddr[9:2]`，`0x00400000` 恰好对应 0 号字，程序第一条指令就放在那里 |
| 存储器按字编址 | RISC-V 指令固定 32 位，指令存储器没有字节访问需求；数据存储器当前只被 `lw`/`sw`（字访问）使用，取 `f[9:2]` 做字索引与 ROM 风格一致 |
| 分支判断复用 ALU | 比较类运算本来就存在（slt/sltu），让 ALU 顺便输出条件信号 `con`，控制单元不需要额外的比较器 |
| 三处多路选择器集中放在 CPU.v | b 操作数、写回数据、下地址是单周期数据通路的三个决策点，集中放置便于对照控制真值表检查 |
| B/J 型立即数编码省去最低位 | 这两类立即数最低位恒为 0（目标地址按 2 字节对齐），编码时把有效位上移 1 位，多出 1 位表示更大的偏移范围 |
| 复位只作用于 PC | 寄存器堆用 `initial` 清零（仿真有效、综合转为初值）；RAM 无初值，程序自行先写后读。单周期数据通路中其余寄存器型状态只有这三处 |
| 自检程序末尾 `jal x0, 0` 自循环 | 单周期 CPU 没有停机指令，用原地跳转让程序停在末尾；写入 x0 的返回地址会被寄存器堆忽略 |
