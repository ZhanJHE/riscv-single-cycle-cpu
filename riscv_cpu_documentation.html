项目概述

本RISC-V单周期CPU项目实现了一个基础的32位RISC-V处理器，采用单周期执行方式，每个时钟周期完成一条指令的执行。项目包含完整的指令流水线前段，包括取指、译码、执行和访存阶段。

CPU采用模块化设计，将各个功能单元独立实现，便于理解各模块的功能和相互之间的信号连接。整个处理器支持基本的RISC-V指令集，包括算术运算、逻辑运算、分支跳转等指令类型。

1. CPU.v - CPU顶层模块

CPU.v是整个处理器的顶层模块，负责连接和协调各个子模块，实现完整的数据通路和控制通路。该模块实例化了程序计数器、指令译码器、控制单元、寄存器堆和算术逻辑单元等核心组件。

端口定义

信号名称 方向 位宽 功能描述
clk input 1 系统时钟信号
rst input 1 系统复位信号，高电平有效
pcAddr output 32 当前程序计数器值，用于从ROM取指令
insData input 32 从ROM获取的32位指令数据

内部信号定义

CPU模块定义了多个内部连接信号，用于连接各子模块：

  • nextaddr - 下一条指令的地址
  • curraddr - 当前指令地址
  • addr4 - 当前地址加4
  • rdata1, rdata2 - 寄存器堆读出数据
  • rwdata - 寄存器堆写入数据
  • a, b - ALU输入操作数
  • f - ALU运算结果
  • rs1, rs2, rd - 寄存器编号
  • opcode - 操作码（7位）
  • func - 功能码（3位）
  • dis - 功能7位码
  • con - 条件判断结果
  • rwe, mwe - 寄存器和存储器写使能
  • isimm, isfpc, isfm, ispc4 - 各种数据选择控制信号
  • imm12, imm20 - 立即数
  • imm12_exp, imm20_exp - 符号扩展后的立即数
  • addr_branch, addr_jal, addr_jalr - 各种跳转地址
  • pcsource - PC源选择信号
  • aluop - ALU操作码

关键逻辑

  • PC地址输出：将当前PC值输出到pcAddr端口，用于从ROM取指令
  • 立即数符号扩展：将12位立即数符号扩展到32位 
    assign imm12_exp={{20{imm12[11]}},imm12};
  • ALU操作数准备：a操作数固定来自rdata1，b操作数来自符号扩展的立即数（当前实现） 
    assign a=rdata1;
assign b=imm12_exp;
  • 寄存器写回数据：当前实现直接使用ALU结果作为写回数据 
    assign rwdata=f;
  • PC更新：当前实现采用顺序执行，PC值加4 
    assign nextaddr=curraddr+4;
注意：当前CPU.v中的PC更新、ALU操作数b和数据通路存在TODO标记，需要根据完整指令集需求进行修改和完善，特别是对于分支跳转指令的处理。

2. top.v - 测试顶层模块

top.v是整个系统的顶层测试模块，用于实例化CPU和指令存储器ROM，并提供时钟和复位信号。该模块是硬件验证的基础框架。

端口定义

信号名称 方向 位宽 功能描述
clk input 1 系统时钟输入
rst input 1 系统复位输入

内部信号

  • addr - 32位地址信号，连接CPU的pcAddr输出
  • insdata - 32位指令数据，从ROM输出连接到CPU

模块实例化

CPU mycpu(
    .clk(clk),
    .rst(rst),
    .pcAddr(addr),
    .insData(insdata)
);

// 实例化ROM
rom insrom(
    .addr(addr[9:2]),
    .data(insdata)
);

关键特性

  • 地址对齐：ROM地址使用addr[9:2]，即字对齐地址（除以4），因为每条指令占4字节
  • ROM大小：地址线使用8位，可寻址256个32位字（1KB指令存储空间）
  • 简单连接：top.v提供了CPU和ROM之间的简单连接，未包含数据存储器RAM的连接
注意：top.v中存在TODO标记，可能需要添加数据存储器RAM的实例化和连接，以支持加载和存储指令的完整功能。

3. pc.v - 程序计数器

pc.v实现了程序计数器功能，用于存储当前正在执行的指令地址。PC是处理器中最重要的状态寄存器之一，控制指令的执行流程。

端口定义

信号名称 方向 位宽 功能描述
clk input 1 时钟信号，上升沿触发PC更新
rst input 1 复位信号，高电平有效
nextaddr input 32 下一条指令的地址
addr output 32 当前程序计数器值

功能实现

module pc(
    input clk,
    input rst,
    input[31:0] nextaddr,
    output reg [31:0] addr
);
    always @(posedge clk)
    begin
        if(rst==1'b1)
            addr<=32'h00400000;
        else
            addr<=nextaddr;
    end
endmodule

关键特性

  • 同步时序逻辑：使用always @(posedge clk)实现同步更新
  • 复位功能：复位时将PC初始化为0x00400000，这是RISC-V的标准起始地址
  • 地址更新：非复位状态下，PC值更新为nextaddr的值
  • 寄存器输出：addr定义为output reg，在时钟沿更新时保持稳定

工作原理

在每个时钟上升沿，PC模块检查复位信号。如果复位信号有效（高电平），PC被设置为初始地址0x00400000。否则，PC更新为输入的nextaddr值。这样实现了PC的顺序执行和跳转功能。

4. rom.v - 指令存储器

rom.v实现了指令存储器功能，用于存储程序指令。这是一个只读存储器，在初始化时从外部文件加载指令数据，运行时只能读取不能写入。

端口定义

信号名称 方向 位宽 功能描述
addr input 8 存储器地址输入（字地址）
data output 32 从指定地址读取的32位指令数据

功能实现

module rom(
    input [7:0] addr,
    output [31:0] data
);
    reg[31:0] insData[0:63];
    initial
        $readmemh("../../../../insData.txt",insData);
    assign data=insData[addr];
endmodule

关键特性

  • 存储容量：定义了64个32位存储单元（256字节），实际使用0:63索引
  • 地址宽度：8位地址输入，可寻址256个位置，但只定义了64个有效单元
  • 文件初始化：使用$readmemh系统任务从insData.txt文件加载十六进制格式的指令数据
  • 异步读取：使用assign实现组合逻辑读取，地址变化时数据立即输出
  • 只读特性：没有写使能信号和数据输入端口，实现了ROM的只读特性

工作原理

ROM模块在仿真初始化阶段从外部文件insData.txt读取指令数据到内部存储器数组。运行时，根据输入的addr值，直接输出对应地址的32位指令数据。由于使用assign语句，读取操作是异步的，不依赖于时钟信号。

文件格式

insData.txt文件应包含十六进制格式的指令数据，每行一个32位指令。例如：

00000000
00000001
00000002
00000003
注意：ROM地址是字地址（每项对应4字节），与PC的地址需要右移2位对齐。top.v中通过addr[9:2]实现了这种对齐。

5. ID.v - 指令译码器

ID.v实现了指令译码功能，用于解析32位RISC-V指令的各个字段，提取操作码、寄存器编号、立即数等信息。译码器是理解指令含义的关键模块。

端口定义

信号名称 方向 位宽 功能描述
ins input 32 输入的32位指令
rs1 output 5 源寄存器1编号
rs2 output 5 源寄存器2编号
rd output 5 目标寄存器编号
opcode output 7 操作码
funct3 output 3 功能码3
funct7 output 1 功能码7（仅第30位）
imm12 output 12 12位立即数
imm20 output 20 20位立即数

指令字段提取

// 标准RISC-V指令格式字段提取
assign opcode=ins[6:0];
assign rd=ins[11:7];
assign funct3=ins[14:12];
assign rs1=ins[19:15];
assign rs2=ins[24:20];
assign funct7=ins[30];

指令类型识别

ID.v实现了基本的指令类型识别逻辑：

wire I_type,S_type,B_type,J_type,U_type;
// 0000011  I型指令（如LOAD、ALU立即数指令）
assign I_type=~ins[6]&~ins[5]&~ins[3]&~ins[2]&ins[1]&ins[0];
// 1100011  B型指令（分支指令）
assign B_type=(&ins[6:5])&~(|ins[4:2])&(&ins[1:0]);
// 0100011  S型指令（存储指令）
assign S_type=~ins[6]&ins[5]&~(|ins[4:2])&(&ins[1:0]);

立即数提取

根据指令类型提取不同格式的立即数：

assign imm12={12{I_type}}&ins[31:20]|
             {12{B_type}}&{ins[31],ins[7],ins[30:25],ins[11:8]}|
             {12{S_type}}&{ins[31:25],ins[11:7]};

关键特性

  • 组合逻辑：所有译码操作使用assign语句实现，纯组合逻辑
  • 字段提取：按照RISC-V标准指令格式提取各个字段
  • 类型识别：通过opcode模式识别I型、B型、S型等指令类型
  • 立即数重组：根据不同指令类型重组立即数字段

RISC-V指令格式

  • R型：rs1[19:15], rs2[24:20], funct3[14:12], rd[11:7], funct7[31:25]
  • I型：imm[31:20], rs1[19:15], funct3[14:12], rd[11:7]
  • S型：imm[31:25], rs2[24:20], rs1[19:15], funct3[14:12], imm[11:7]
  • B型：imm[31|7], imm[30:25], rs2[24:20], rs1[19:15], funct3[14:12], imm[11:8]
注意：ID.v中的imm20提取逻辑标记为TODO，需要完善U型和J型指令的20位立即数提取。当前实现主要关注I型、B型和S型指令。

6. ControlUnit2.v - 控制单元

ControlUnit2.v实现了控制单元功能，根据译码器输出的操作码和功能码生成各个控制信号，控制数据通路的操作。控制单元是CPU的大脑，决定如何执行每条指令。

端口定义

信号名称 方向 位宽 功能描述
opcode input 7 指令操作码
funct3 input 3 功能码3
funct7 input 1 功能码7（第30位）
condition input 1 分支条件判断结果（B型指令使用）
pcSourceCode output 2 PC源选择：00=顺序，01=分支，10=JAL，11=JALR
regWe output 1 寄存器写使能
memWe output 1 存储器写使能
aluOpCode output 4 ALU操作码
bIsImm output 1 ALU的b操作数是否为立即数
bIs20bImm output 1 是否为20位立即数指令
regDataIsFromMem output 1 寄存器写回数据是否来自存储器
regDataIsFromPC4 output 1 寄存器写回数据是否来自PC+4

当前实现

module ControlUnit(
    input [6:0] opcode,
    input [2:0] funct3,
    input funct7,
    input condition,
    output [1:0]pcSourceCode,
    output regWe,
    output memWe,
    output [3:0] aluOpCode,
    output bIsImm,
    output bIs20bImm,
    output regDataIsFromMem,
    output regDataIsFromPC4
);
    wire i_type=~(|opcode[6:5])&opcode[4]&~(|opcode[3:2])&(&opcode[1:0]);

    assign pcSourceCode=2'b00;
    assign regWe=1'b1;
    assign memWe=1'b0;
    assign bIsImm=1'b1;
    assign bIs20bImm=1'b0;
    assign regDataIsFromMem=1'b0;
    assign regDataIsFromPC4=1'b0;
    assign aluOpCode=4'b0011;
endmodule

控制信号功能

  • pcSourceCode[1:0]：控制下一个PC值的来源
    • 00：顺序执行（PC+4）
    • 01：分支跳转
    • 10：JAL指令跳转
    • 11：JALR指令跳转
  • regWe：控制寄存器堆的写操作，1表示允许写回
  • memWe：控制数据存储器的写操作，1表示执行存储指令
  • aluOpCode[3:0]：控制ALU执行的具体运算操作
  • bIsImm：选择ALU的b操作数来源，1表示使用立即数
  • regDataIsFromMem：LOAD指令时选择从存储器读取的数据作为写回数据
  • regDataIsFromPC4：JAL/JALR指令时使用PC+4作为写回数据

ALU操作码定义

  • 0000：加法
  • 0001：逻辑左移
  • 0010：有符号小于比较
  • 0011：无符号小于比较
  • 0100：异或
  • 0101：逻辑右移
  • 0110：或
  • 0111：与
  • 1000：减法
  • 1001：等于比较
  • 1010：不等于比较
  • 1011：有符号大于等于比较
  • 1100：无符号大于等于比较
  • 1101：算术右移
  • 1110：JALR地址计算
  • 1111：LUI指令
注意：当前ControlUnit2.v的实现是简化版本，所有控制信号都设置为固定值。完整的控制单元需要根据不同的opcode、funct3和funct7组合生成对应的控制信号，以支持完整的RISC-V指令集。

7. alu.v - 算术逻辑单元

alu.v实现了算术逻辑单元功能，执行各种算术运算、逻辑运算和比较操作。ALU是CPU中执行计算的核心部件，根据操作码执行相应的运算。

端口定义

信号名称 方向 位宽 功能描述
dataA input 32 操作数A（通常来自寄存器rdata1）
dataB input 32 操作数B（来自寄存器rdata2或立即数）
opcode input 4 ALU操作码
result output 32 运算结果
con output 1 条件判断结果（用于分支指令）

中间信号

wire signed [31:0] signed_dataA = dataA;
wire signed [31:0] signed_dataB = dataB;
wire [31:0] sum = dataA + dataB;
wire [31:0] diff = dataA - dataB;

比较信号

wire lt_signed = (signed_dataA < signed_dataB);
wire lt_unsigned = (dataA < dataB);
wire eq = (dataA == dataB);
wire ne = (dataA != dataB);
wire ge_signed = (signed_dataA >= signed_dataB);
wire ge_unsigned = (dataA >= dataB);

ALU操作实现

always @(*) begin
    result = 0;
    con = 0;

    case(opcode)
        // 加法
        4'b0000: result = sum;

        // 逻辑左移
        4'b0001: result = dataA << dataB[4:0];

        // 有符号小于比较
        4'b0010: begin
            result = {31'b0, lt_signed};
            con = lt_signed;
        end

        // 无符号小于比较
        4'b0011: begin
            result = {31'b0, lt_unsigned};
            con = lt_unsigned;
        end

        // 异或
        4'b0100: result = dataA ^ dataB;

        // 逻辑右移
        4'b0101: result = dataA >> dataB[4:0];

        // 或
        4'b0110: result = dataA | dataB;

        // 与
        4'b0111: result = dataA & dataB;

        // 减法
        4'b1000: result = diff;

        // 等于比较
        4'b1001: begin
            result = 0;
            con = eq;
        end

        // 不等于比较
        4'b1010: begin
            result = 0;
            con = ne;
        end

        // 有符号大于等于
        4'b1011: begin
            result = 0;
            con = ge_signed;
        end

        // 无符号大于等于
        4'b1100: begin
            result = 0;
            con = ge_unsigned;
        end

        // 算术右移
        4'b1101: result = signed_dataA >>> dataB[4:0];

        // JALR地址计算
        4'b1110: result = sum & ~32'b1;

        // LUI高位立即数加载
        4'b1111: result = dataB << 12;

        default: begin
            result = 0;
            con = 0;
        end
    endcase
end

关键特性

  • 组合逻辑：使用always @(*)实现纯组合逻辑，输出立即响应输入变化
  • 有符号/无符号支持：通过signed类型支持有符号运算
  • 移位操作：支持逻辑左移、逻辑右移、算术右移
  • 比较操作：支持有符号和无符号的各种比较
  • 条件输出：con信号输出布尔比较结果，用于分支判断
  • JALR支持：特殊处理JALR指令的地址计算（最低位清零）
  • LUI支持：支持LUI指令的高位立即数加载

移位量限制

所有移位操作使用dataB[4:0]，即只使用低5位作为移位量，符合RISC-V规范（移位量限制在0-31之间）。

8. RegFiles.v - 寄存器堆

RegFiles.v实现了RISC-V标准的32个通用寄存器堆，提供双端口读和单端口写功能。寄存器堆是CPU中用于临时存储数据和地址的重要组件。

端口定义

信号名称 方向 位宽 功能描述
clk input 1 时钟信号，上升沿触发写操作
raddr1 input 5 读端口1地址
rdata1 output 32 读端口1数据
raddr2 input 5 读端口2地址
rdata2 output 32 读端口2数据
waddr input 5 写端口地址
wdata input 32 写端口数据
we input 1 写使能信号

功能实现

module RegFiles(
    input clk,
    input [4:0] raddr1,
    output [31:0] rdata1,
    input [4:0] raddr2,
    output [31:0] rdata2,
    input [4:0] waddr,
    input we,
    input [31:0] wdata
);
    reg[31:0] regs[1:31];
    integer i;
    initial
        for(i=1;i<32;i=i+1) regs[i]=32'b0;

    assign rdata1=(raddr1==5'b00000)?32'b0:regs[raddr1];
    assign rdata2=(raddr2==5'b00000)?32'b0:regs[raddr2];

    always @(posedge clk)
        if(we)
            if(waddr!=4'b00000)
                regs[waddr]<=wdata;
endmodule

关键特性

  • 32个寄存器：定义了regs[1:31]，共31个通用寄存器（x1-x31）
  • 零寄存器x0：通过硬件逻辑实现，读取地址0时返回0，写入地址0时忽略
  • 双端口读：可以同时读取两个不同的寄存器（raddr1和raddr2）
  • 异步读取：使用assign实现组合逻辑读取，地址变化时数据立即输出
  • 同步写入：使用always @(posedge clk)实现同步写入，时钟沿触发
  • 写使能控制：只有we信号为1时才执行写操作
  • 零寄存器保护：写入地址0时自动忽略，保持x0恒为0

初始化

在initial块中，使用循环将所有寄存器初始化为0。这在仿真时有用，实际硬件中复位逻辑也需要确保寄存器初始状态。

读操作时序

  • 读操作是异步的，不依赖时钟
  • 读取地址0时直接返回0（零寄存器）
  • 读取非零地址时返回对应寄存器的当前值

写操作时序

  • 写操作是同步的，在时钟上升沿执行
  • 只有在we=1时才执行写操作
  • 写入地址0时自动忽略（保护零寄存器）
  • 使用非阻塞赋值<=，避免仿真竞争
注意：寄存器堆的写地址判断使用waddr!=4'b00000，这里应该是5'b00000（5位全零），当前实现存在一个小错误，建议修正为waddr!=5'b00000。

9. ram.v - 数据存储器

ram.v实现了数据存储器功能，用于存储程序运行时的数据。这是一个可读写存储器，支持数据的加载和存储操作，实现LOAD和STORE指令的数据访问。

端口定义

信号名称 方向 位宽 功能描述
clk input 1 时钟信号，写操作同步
we input 1 写使能信号（1=写入，0=读取）
addr input 8 8位地址（256个32位存储单元）
data_in input 32 32位输入数据（写操作）
data_out output 32 32位输出数据（读操作）

功能实现

module ram(
    input clk,
    input we,
    input [7:0] addr,
    input [31:0] data_in,
    output [31:0] data_out
);
    reg [31:0] memory [0:255];

    // 同步写入
    always @(posedge clk) begin
        if (we) begin
            memory[addr] <= data_in;
        end
    end

    // 异步读取
    assign data_out = memory[addr];
endmodule

关键特性

  • 存储容量：256个32位存储单元（1KB数据存储空间）
  • 地址宽度：8位地址线，可寻址256个位置
  • 同步写入：写操作在时钟上升沿执行，使用非阻塞赋值
  • 异步读取：读操作使用assign实现，地址变化时数据立即输出
  • 写使能控制：只有在we=1时才执行写操作
  • 读操作不受we影响：无论we为何值，都可以进行读操作

存储器初始化

当前RAM实现没有初始化逻辑，所有存储单元的初始值未定义。在实际应用中：

  • 仿真时可以使用$readmemh从文件加载初始数据
  • 硬件中上电后存储器内容是随机的，需要通过程序初始化

读写时序

  • 写操作：在时钟上升沿，如果we=1，将data_in写入memory[addr]
  • 读操作：组合逻辑，data_out始终输出memory[addr]的当前值
  • 同时读写：可以同时进行读写操作，读操作会输出新写入的数据（或旧数据，取决于具体实现）

与LOAD/STORE指令的配合

  • LOAD指令：计算地址 → 设置we=0 → 读取data_out → 写回寄存器
  • STORE指令：计算地址 → 设置we=1 → 写入data_in
注意：当前RAM模块未在top.v中实例化和连接。要支持完整的LOAD和STORE指令功能，需要在top.v中实例化ram模块，并根据控制单元的memWe信号连接相应的数据通路。

总结

本RISC-V单周期CPU项目实现了基本的处理器架构，包含完整的数据通路和控制通路。各个模块协同工作，实现了指令的取指、译码、执行和访存功能。

主要特点

  • 模块化设计：每个功能单元独立实现，便于理解和修改
  • 单周期执行：每条指令在一个时钟周期内完成
  • 标准RISC-V格式：遵循RISC-V指令集规范
  • 可扩展性：支持添加新的指令类型和功能

待完善功能

  • CPU.v中的PC更新逻辑需要支持分支和跳转指令
  • 控制单元需要根据不同指令生成正确的控制信号
  • ID.v需要完善U型和J型指令的立即数提取
  • top.v需要集成RAM模块以支持数据存储指令
  • RegFiles.v中的零寄存器判断逻辑需要修正

数据通路概述

  1. 取指阶段：PC → ROM → 指令寄存器
  2. 译码阶段：ID模块解析指令字段，控制单元生成控制信号
  3. 执行阶段：寄存器堆读取数据 → ALU执行运算
  4. 访存阶段：根据需要访问RAM（当前未连接）
  5. 写回阶段：ALU结果或RAM数据写回寄存器堆
